# dsh-language-guard 验收清单

用途：本文件是 `dsh-language-guard` 的验收门禁。三份清单逐条可判定，任一条「不通过」即阻断发布，不允许以「差不多能用」放行。

依赖与环境（判定时的基准）：

- DSH Desktop 运行时版本 `0.2.1-rc.2`（`/package.json`、`/dsh/node_modules/@deepseek-ai/dsh/package.json`）。
- DSH 实现与官方规范文档位于 `app.asar`，读取方式：`python3 /Volumes/data/dsh-cn-think/asar_tool.py cat <asar 内路径>`，另有 `ls` / `tree` / `grep` 子命令。
- 规范来源（以下路径均在 asar 内）：
  - `/dsh/node_modules/@deepseek-ai/dsh-agent-preset/skills/cordis-plugin-development/SKILL.md`
  - 同目录 `references/host-plugin.md`、`references/ui-plugin.md`、`references/practices.md`、`references/verification.md`、`references/user-actions.md`
  - 同目录 `templates/decoration/{package.json,cordis.patch.yml,lib/index.js,client.js,locale/en.json,icon.svg}`
  - `/dsh/node_modules/@deepseek-ai/dsh-package-manifest/README.zh.md`（`engines.dsh`、`dsh.manifestVersion` 语义）
  - `/dsh/node_modules/@deepseek-ai/dsh-plugin-manager/README.zh.md`（安装、版本兼容检查、`install_bundle`）
  - `/dsh/node_modules/@deepseek-ai/dsh-system-prompt/README.zh.md`（`section()`、order、渲染与日志）
  - `/dsh/node_modules/@deepseek-ai/dsh-client-locale/README.zh.md`（`ctx.locale.register` / `addLanguage` / 切换）
  - `/dsh/node_modules/@deepseek-ai/dsh-settings/README.zh.md`（`.volatile()` 与 `configure({ auto: false }, ctx.fiber)`）

判定约定：

- 「判定」列写通过阈值，必须能在不靠主观感觉的情况下判真假；「验证方式」列给出可复制的命令或明确操作步骤。
- 标注「人工判定」的条目允许主观成分，但必须留下证据（截图、会话链接或日志片段）。
- 「结果」列由验收人填 `通过` / `不通过` / `未验证`。`未验证` 默认按不通过处理；唯一例外是 B5、D11 这类渲染检查在无浏览器控制时可标「未验证」，但发布前必须补验。
- 机制细节（三档文案、order 落点、schema 字段名、控件形态、slot 落点、manifest 三处联合要求）以 `docs/decisions/01-mechanism.md`、`02-panel.md`、`03-manifest.md` 为准；本清单只约束可观测的判定标准，不重复决策内容。三份决策文档改动时，对应条目必须同步改，不得只改文档。

## 五、一键自检脚本（用于 A/B/C/D 组、E1、F18、M 组与部分 R 组）

脚本落在仓库 `scripts/verify-checklist.sh`（**不进 `files` 白名单**，与 `scripts/verify-manifest.mjs` 一样只存在于仓库），在包根目录执行：

```bash
bash scripts/verify-checklist.sh; echo "退出码=$?"
```

> **看退出码时不要接管道**。`bash scripts/verify-checklist.sh | tail -5` 的 `$?` 是 `tail` 的退出码，恒为 0——这会让「有 FAIL 却报成功」。要判结果就单独 `echo $?`，或看输出里的 `PASS n / FAIL n` 汇总行。

**CI 模式（`LG_CI=1`）**：GitHub Actions 里以 `LG_CI=1 bash scripts/verify-checklist.sh` 运行，只调整一条、放宽一条与环境绑定的判据，其余照常跑：

| 条目 | CI 里的处理 | 原因 |
|---|---|---|
| R16 | 加 `--ignore-scripts` | CI checkout 默认不拉 tag，`prepublishOnly` → `verify-release.mjs` 的 tag 校验必然失败；跳过它只保留 npm 自身的打包/白名单/名称校验 |
| R23 | 只断言 `unpackedSize`，不断言 `size` | `size` 是 gzip 后的字节数，受 zlib 版本影响；`unpackedSize` 是文件内容原始字节总和，与压缩器无关 |

R23 的处理依据是实测，不是推断。0.3.4 同一 commit 上：本机 `size=63634`、CI `size=63632`（差 2 字节），而两边 `unpackedSize` 都是 `186818`，完全相同。保留 `unpackedSize` 断言就足以守住「改了进包文件却没同步文档数字」这个缺口——内容一变 `unpackedSize` 必变，与压缩器无关。

因此 CI 的汇总行现在与本机一致，都是 `PASS 74   FAIL 0   TODO 0`，不再有 `SKIP` 段。**但 R23 在 CI 上确实少断言了 `size` 这一个数**：若只在 CI 发布、从不本机跑 `npm test`，`size` 漂移不会被发现。本机发布流程仍断言全部两个数。

退出码语义（实现工程师跑门禁时按这个判，不要只看有没有红字）：

| 退出码 | 含义 | 该怎么做 |
|---|---|---|
| `0` | 机械可判项全部通过 | 继续跑人工项 |
| `1` | 存在真实不通过项 | 必须修，逐条看 `FAIL` 行 |
| `2` | 存在「尚未实现」项（`lib/` 或 `client.js` 还没落盘） | **不是失败，也不能算通过**；等文件齐了重跑 |

脚本要点：

- 入口路径**不写死**：从 `package.json` 的 `exports["."]` 读（本包为 `./lib/index.js`），读不到才回退到 `lib/index.js`。
- **自动兜住 optional peer**：`@deepseek-ai/schemastery` 与 `@deepseek-ai/dsh-llm` 只在宿主运行时提供，仓库根没有 `node_modules`。脚本检测到缺失时自动建最小 stub（`Proxy` 链式 stub + `createUserMessage`），`trap` 在退出时删除；已有真实依赖时一律不动。因此 A2/C1 的 `import()` 在干净 checkout 与 CI 上也能跑，不会出现「环境导致的假失败」。
- **只认代码行，不认注释**：`hits()` / `hits_n()` 会先剥掉整行注释（`*`、`//`、`/*` 开头），避免「注释里写了 `await next()` 就算实现」这类假通过。
- Host 侧判据扫整个 `lib/` 目录（实现分散在 `lib/index.js`、`lib/cycle.js`、`lib/state.js`、`lib/text.js`、`lib/commands.js`），只有 C1/C9 这类「必须在入口文件里」的条目才锁定入口文件。
- 依赖具体文件的条目**先判文件是否存在**，缺失时输出 `TODO <条目> (尚未实现：…)` 并计入 `missing`——不会因为 `grep` 打到不存在的文件而误判 PASS，也不会因 `node` 抛栈把整个脚本崩掉。

| 项 | 说明 |
|---|---|
| 入口路径 | 从 `package.json` 的 `exports["."]` 读，不写死文件名 |

## 六、门禁规则

1. 一、二、三、四组任一条「不通过」即阻断发布；F3/F4 的档位说明与 order 必须与 `docs/decisions/01-mechanism.md` 逐字比对（该文档是唯一真源），不得以「文中提到了三档」代替比对；`未验证` 视同不通过（B5/D11 视觉项在无浏览器控制时允许标注「未验证」并在交付报告中声明，但发布前必须补验）。
2. `bash scripts/verify-checklist.sh; echo "退出码=$?"` 的退出码按语义读：`0` 才可进入人工项；`1` 一律视为阻断（真实缺陷）；`2`（存在 `TODO 尚未实现`）**不得写成「通过」，也不得当作失败**，报告中必须原样写「X 项尚未实现」，等文件落盘后重跑。**禁止接管道取退出码**（`... | tail` 拿到的是 `tail` 的 0，会把缺陷报成成功）；脚本的汇总行与结论同时写 stderr，就是为了在被截断时仍可见。
3. 档位与落点类判定以决策文档为准，清单只做索引：三档控件形态见 `docs/decisions/02-panel.md` 3.1（radio group），快速切换落点见同文档 5.1（`sidebar.footer.action`），manifest 三处联合要求见 `docs/decisions/03-manifest.md` 第 2.2 节与 9.1。决策文档改动时本条目的判定文字必须同步，不得只改文档不改清单。
4. 每轮修复后重跑对应组，不重跑全量时必须在报告中写明复验范围与理由。
5. 判定结果与证据（命令输出、截图、会话链接）随 PR 或发布说明归档，不接受口头结论。
