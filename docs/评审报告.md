## 四、可用性

### 4.1 安装路径（README 三条路径的实机可操作性）

README 两版均给出三条安装路径：

1. **GUI**：侧栏 Plugins 面板 → Add plugin → 粘贴 `https://github.com/58fly/dsh-language-guard` → Enable now

### 7.3 对实现质量的整体评价

代码规模 1604 行（`lib/` 619 行 + `client.js` 985 行），结构清晰：`lib/text.js` 是四段文案的唯一真源、`lib/state.js` 只做规范化、`lib/cycle.js` 的 D 档门禁六层判断逐层可读、`client.js` 的字典与控件分离。

三处设计判断值得肯定：

1. **mid section 用 5100 而非 5000**：同序时会因 name 字典序排到 `tools:sdk` 之前，失去「工具说明之后重申」的作用。这个 100 的偏移是有依据的，不是随手写的。
2. **D 档走 `agent/pre-step` 改写 `decision.messages` 而非 `agent.inject()`**：保住「Model-visible ⟺ logged」不变式——注入的内容作为一条真实会话记录出现，用户能在会话日志里看到。这是本项目最核心的合规判断。
3. **`addLanguage` 不调用**：分清「界面语言」与「目标语言」两件事，不越界改宿主的语言菜单。

一处可改进：`client.js` 985 行单文件，控件、字典、样式全在一个 `__ModuleLoader__.load` 的 factory 里。这是官方模板的形态（factory 内不能有跨文件 import），受限于装载契约，不算缺陷；但如果后续要加控件，建议把纯函数部分（`languageLabel` / `format` / 校验）抽成同文件内的独立段落并加分隔注释，降低阅读成本。
