## 1. 用途

`dsh-language-guard` 是一个 DSH 插件（Host + Client 双半身），做一件事：**让 agent 在整段会话里用指定语言思考和回答**，默认简体中文。

它通过三条常驻 system prompt section（首、中、尾）施加约束，用 `agent/pre-step` 在 D 档周期性追加自检提醒，并在设置页与侧栏提供配置入口。

不做什么：

- 不改写模型的流式推理增量（不伪造「思考过程」）；
- 不监听系统提示词装配事件去增删宿主文本（只用 `ctx.systemPrompt.section()` 声明自己的段落）；
- 不 append 新 type 的会话事件；
- 不依赖任何第三方运行时包（`dependencies` 为空）。

## 3. Host 半实现要点

### 3.1 三个常驻 section

| name | order | B 档 | C 档（默认） | D 档 |
| --- | --- | --- | --- | --- |
| `language-guard:head` | `-2000` | 有文本 | 有文本 | 有文本 |
| `language-guard:mid` | `5100` | 返回 `""`（被过滤，不留空行） | 有文本 | 有文本 |
| `language-guard:tail` | `11200` | 有文本 | 有文本 | 有文本 |

- order 一律写**数字字面量**：`ctx.systemPrompt.section()` 对非有限数字直接抛 `TypeError`；`mid` 用 `5100` 而不是 `5000`，因为 `tools:sdk` 恰好是 `5000`，同序时 `language-guard:mid` 会按 name 的 code-unit 字典序排到工具说明之前，失去「工具说明之后重申」的作用。
- 三个 section **一次性注册、永不 dispose**：切档只切 `text()` 返回值，避免同名重复注册抛 `prompt section "…" is already registered`。
- 全部 `interpolate: false`：用户 `extraRules` 里若含 `{{`，插值会抛错并让整份 system prompt 装配失败。
- 三个 section 都不带 `complete: true`（>1 个会抛 `multiple complete prompt sections are active`）。
- 文本在一次会话内稳定：`text()` 只读配置与内存覆盖，不读轮次、时间、随机数，避免 in-history 替换与 KV cache 失效。

### 3.2 配置读取

`schema` 的字段是 schemastery 的 **ref**，不是普通值。`readField()` 统一处理：

```js
const ref = config?.[field];
if (ref !== undefined && ref !== null && typeof ref.get === 'function') return ref.get();
return ref;
```

所有取值都是**函数式**（`strength()`、`language()` …），在 `text()` 与 `pre-step` 里现取，不缓存到闭包外——配置改动后无需重启、无需重新 apply，下一步装配即生效。

非法值不抛错：`normalizeStrength` / `normalizeInterval` 回退到默认值并通过 `warnOnce()` 各告警一次（避免每步刷屏）。

### 3.2.1 自动语言模式（`lib/language.js` + `lib/index.js`）

0.2.0 新增。目标语言的来源从「只有配置值」变成「配置值或界面语言」，判定与解析全部在纯函数模块 `lib/language.js` 里，`lib/index.js` 只负责把 ctx 上的信号喂进去。

**三态模式。** `Config.languageMode` 是 `'' | 'auto' | 'manual'`，**默认空串而不是 `'auto'`**。这是本功能最关键的一个决定：

- 默认写 `'auto'` 会把「用户从没设过模式」与「用户显式选了自动」抹成同一个状态，schema 再也分不出来；
- 老用户手选过 `targetLanguage`（比如 `ja`），升级后就会被界面语言静默覆盖成 `zh-CN` —— 这正是票面明令禁止的「静默覆盖用户的手动选择」。

空串的语义是「未选择，按迁移规则推断」，规则在 `effectiveMode()`：

| `languageMode` | `targetLanguage` | 有效模式 |
| --- | --- | --- |
| `'auto'` | 任意 | auto |
| `'manual'` | 任意 | manual |
| `''` | `=== 'zh-CN'`（默认值） | auto（新用户，跟随界面） |
| `''` | `!== 'zh-CN'` | **manual**（老用户手选过，尊重既有选择） |

用户一旦显式选过模式，`languageMode` 不再是空串，迁移规则永久失效。

**解析链只有两环。** `locale.preference`（界面语言）→ `targetLanguage` 配置值。**没有系统语言这一档**：Host 半跑在 `ELECTRON_RUN_AS_NODE=1` 的子进程里，`require("electron")` 抛 `Cannot find module 'electron'`，`Intl.DateTimeFormat().resolvedOptions().locale` 恒返回 `en-US`（本机系统实为 `zh-Hans-CN`）——这个信号会把中文用户误判成英文，宁可不用，也不硬编一个假信号。依据见 `docs/research/04-auto-language.md` 与票 #13 的 Answer D 节。

映射规则（`mapPreference`）：`zh` 开头 → `zh-CN`，`en` 开头 → `en`，其余取原样的合法 BCP-47。之所以不细分 `zh-TW`：DSH 的界面语言枚举只有简体中文与 English（`dsh-client-locale` 的 `locale.preference`），解析不到繁體中文，想用必须手动选——面板在自动态会显示这条提示。

**界面语言怎么拿、怎么刷新。** 不在 `text()` 里读：

- `apply` 期在 `ctx.inject(['settings'], child => …)` 里调一次 `child.settings.describe()`，把 `ns === 'locale'` 那条 entry 的 `value.preference` 缓存进闭包；
- 同时 `child.on('settings/document-updated', ns => …)` 订阅，`ns` 是 `locale` 或 `language-guard` 时重读。

不每次现读的理由：`describe()` 单次约 2–5 ms，且要遍历全部 entry 做 schema 投影，而 system prompt 每步都要装配。不轮询的理由：`document-updated` 已经覆盖了全部变更路径。不会自触发死循环的理由：`dsh-settings` 的 emit 受 `previous?.raw !== raw` 保护，而 `raw` 是 schema + config 的稳定序列化，重复调用不 emit。

`describe()` 抛错时**不炸**：`try/catch` 里退回 `null`，解析链自动落到 `targetLanguage`。这一点有单测覆盖（`test-auto.mjs` 第 7 组）。

**两侧一致性是本功能最可能的静默失效点。** Client 半是独立 bundle（`__ModuleLoader__.load` 的 factory 只能 `require('react')`），不能相对 import 包内文件，所以 `client.js` 里**镜像了一份**同样的纯函数。两份漂移的后果是「面板显示解析成英文，实际注入简体中文」，用户看不出来。因此：

- `scripts/verify-checklist.sh` 的 **M1 / M2** 用正则比对两侧的关键分支必须逐字相同；
- `client.js` 里镜像段落的注释明确写着「改这里必须同步改 `lib/language.js`」；
- `scripts/verify-language.mjs` 的 36 项用例是两侧共同的行为契约。

### 3.3 D 档周期提醒（`lib/cycle.js`）

监听注册在**插件根 ctx**（`ctx.on('agent/pre-step', …)`），payload 自带 `agent`，因此不需要 `agent/created` + per-agent disposer，也不维护计数器（轮次来自 payload 的 `turn`）。

门禁顺序（任一不满足即原样返回）：

1. `const decision = await next()`，`decision.kind === 'reject'` → 返回原 decision；
2. 档位不是 `D` → 返回；
3. `step !== 1` → 返回（只在每轮第一步动手，否则轮次永远不结束）；
4. `decision.messages.length === 0` → 返回（否则会凭空造出一轮）；
5. `turn % N !== 0` → 返回；
6. 已有 `source.kind === 'language-guard'` 的消息 → 返回（幂等，防重复插入）；
7. 子代理跳过：`Math.max(agent.session.header.delegationDepth ?? 0, agent.options.subagentDepth ?? 0) !== 0` → 返回。

插入位置：`const lastClaimed = decision.messages.findLastIndex(m => messages.includes(m))`，然后 `decision.messages.toSpliced(lastClaimed + 1, 0, reminder)`——即插在「本轮真实用户输入之后、runtime context 之前」。

返回 `{ ...decision, messages: entered }`，**必须 spread**：`decision` 上还有 `startsRequestSeries` 等字段，只返回 `{kind, messages}` 会丢。

提醒消息用 `createUserMessage({ content: [{ type: 'text', text }], source: { kind: 'language-guard', form: 'notice', summary: '语言自检' } })` 构造，`source.kind` 绝不能是 `user` 或 `runtime-context`（派生历史据此区分插件注入与真实输入）。

### 3.4 `/language` 命令（`lib/commands.js`）

`ctx.inject(['commands'], child => child.effect(() => child.commands.register({...})))` 懒注册：缺 `commands` 服务的 headless 部署不该让插件永久 pending，否则 section 永远不会注册。

- `/language` → 报告当前语言与配置值；
- `/language ja` → 内存覆盖（不写配置），立即生效；
- `/language reset`（或 `default`）→ 清除覆盖，回到配置值；
- 非法 BCP-47 → 返回 `{kind: 'error'}`，与 `Config.targetLanguage` 用同一正则。

### 3.5 设置表单

`ctx.inject(['settings'], child => child.effect(() => child.settings.configure({ auto: false }, ctx.fiber)))`。

`auto: false` 表示「不要在设置页自动生成页面」，只提供 volatile 配置表单；表单 UI 由 Client 半自己渲染（DSH 不存在 schema→控件的自动渲染器）。

### 3.6 Config schema

```js
export const Config = z.object({
  languageMode:        z.union([z.const(''), z.const('auto'), z.const('manual')]).default('').volatile(),
  targetLanguage:      z.string().default('zh-CN').pattern(BCP47).volatile(),
  strength:            z.union([z.const('B'), z.const('C'), z.const('D')]).default('C').volatile(),
  injectEveryNRounds:  z.number().min(3).max(50).step(1).default(8).volatile(),
  preserveCodeTerms:   z.boolean().default(true).volatile(),
  extraRules:          z.string().default('').volatile(),
  overrideHead:        z.string().default('').volatile(),
});
```

- 用 `@deepseek-ai/schemastery`，**不是** zod：设置页 `volatileForm` 只认 schemastery 的 `meta.volatile`。
- `.volatile()` 必须加在**每个字段**上，不能加在根对象（会报 `volatile fields require a fixed object path without an enclosing volatile field`）。
- `schemastery` 是 peer（optional），不进 `dependencies`。
- `languageMode` 的三态用 `z.union([z.const(...)])` 而不是 `z.string()`：`z.const` 才能在设置页给出可选值列表，`z.string()` 会渲染成自由文本框，用户能敲进任意字符串。

**为什么不实现 `detectedLanguage` 字段。** 0.2.0 明确不做，理由三条：① 检测值一旦落盘就改写了用户手写的 `cordis.patch.yml`（`dsh-config-editor` 的文件锁 + 读 96 KB / 300 ms 的成本，且会重排用户的注释与缩进）；② 多端共享同一个 `$DSH_HOME` 时会互相覆盖；③ 检测值会伪装成「用户偏好」，下次换机器时带来错误的默认。所以解析结果只在内存里算，不落盘。

## 4. Client 半实现要点（`client.js`）

### 4.1 装载与注册

```js
window.__ModuleLoader__.load({
  id: 'dsh-language-guard',           // 必须严格等于包名
  factory(require) { /* … */ return { inject: ['slots', 'locale', 'configForms'], apply }; },
});
```

factory 内无副作用（不写 DOM、不注册全局监听、不 `setInterval`）；只 `require('react')`，不 require 任何 `@deepseek-ai/dsh-client-ui-*` 包。

### 4.2 两个 slot

| slot | 定义 | 用途 |
| --- | --- | --- |
| `plugins.bundle.config` | `key: 'dsh-language-guard'`（bundle 包名）、`locale: 'languageGuard'` | 插件详情页里的配置卡片，处理 `view === 'summary'` 与 `'page'` 两种视图 |
| `sidebar.footer.action` | `id: 'language-guard'`、`order: 100`、`locale: 'languageGuard'` | 侧栏底部的快速语言切换 |

两个 slot 都包在 `ctx.effect(() => ctx.configForms.whileServed(['dsh-language-guard'], () => ctx.slots.inject(…)))` 里：插件未启用时表单服务不可用，此时不应注册 UI。

### 4.3 配置读写

`const form = ctx.configForms.get('dsh-language-guard')`；`inject()` 返回 `{ form, hooks: { guardForm: form }, onSet, onUnset }`。

组件侧优先用 renderer 由 `hooks` 生成的 `useGuardForm(identity)`，拿不到时用 `form` prop 自建 `subscribe`/`getSnapshot` 订阅；两条路径都无条件调用 hook，保证 hook 顺序稳定。写入一律走 `form.set(field, value)` / `form.unset(field)`，Client 半不直接读写 `ctx.config.*`。

### 4.3.1 语言模式控件（0.2.0 新增）

卡片第一组控件是自动 / 手动两态 radio（`fieldset` + 2 个同名 `input[type=radio]`，`name="language-guard-mode"`），后面才是三档强度。

选自动时下面直接写出两行回显（`.lg-mode-current` / `.lg-mode-source`）：

- 「当前解析为 简体中文」——`resolveTargetLanguage` 的结果；
- 来源行——`来自界面语言` / `未识别到界面语言，用配置值兜底`。手动态不显示来源行。

自动态下第 4 项的目标语言控件（文本框 + 5 个 chip）置 `disabled` 而**不隐藏**，与 `injectEveryNRounds` 随 `strength !== 'D'` 置灰的做法一致——隐藏会让布局跳动，用户也会以为「配置丢了」。置灰时说明文案换成「自动模式下不可编辑，切到手动即可自定义」。

**迁移态提示。** `languageMode` 是空串但 `targetLanguage` 不是默认值时，判成手动并额外显示一行 `.lg-mode-migrated` 提示（「你之前手动设置过目标语言，因此保留手动模式」）。这让升级后的老用户不会困惑「为什么我的是手动」。

**界面语言从哪来（0.2.1 修正）。** `inject` 里传 `configForms: ctx.configForms`，组件用 `useUiPreference` 调 `configForms.get('locale')` 读该命名空间的 `preference` 字段——这与 Host 侧 `settings.describe()` 读的是**同一份 remote settings 镜像**，所以面板显示什么、实际就注入什么。

原先读的是 `ctx.locale.getSnapshot().active`，这是个真缺陷：`dsh-client-locale/lib/client.js` 的 `resolveActive()` 在 `preference === void 0` 时返回 `provisional`（浏览器/系统语言派生），而快照只暴露 `{active, locales, revision}`、根本不带 `preference`。于是「英文系统用户首次安装、从未在 DSH 设置里选过语言」时，Host 拿到 `undefined` 走兜底注入简体中文，面板却显示「来自界面语言 · English」——面板撒谎。

改法要点：① 命名空间写成常量 `UI_LOCALE_NS = 'locale'`（既是 `dsh-client-locale` 的 entry id，也是 Host `describe()` 里的 `ns`，两侧必须一致）；② `configForms.get()` 无条件创建 controller，**不要求 locale 已 served**，所以不要再套一层 `whileServed(['locale'])`——那会把「locale 未装配」变成整块不渲染；③ `get()` 抛错时 `try/catch` 吞掉返 `null`，来源行如实写「未识别到」，不能因为读别人的命名空间就炸掉整张卡片。

**写入用 `form.mutate(ops)` 而不是两次 `form.set`。** 模式与语言在语义上是一对（「切到手动并选日语」），分两次写会在中间留下「手动 + 旧语言」的半截状态，而每次写都会触发一次 Loader 的 volatile 提交。快速切换菜单里选具体语言就是这个场景：

```js
form.mutate([
  { op: 'set', path: ['languageMode'], value: 'manual' },
  { op: 'set', path: ['targetLanguage'], value: 'zh-CN' },
]);
```

### 4.4 三档控件

原生 radio group（`fieldset` + `legend` + 3 个同名 `input[type=radio]` + `aria-describedby`），三档说明并列可见，文案逐字取 `01-mechanism.md` 2.1；C 档带「推荐」徽标。不用 `select`：下拉一次只能看一档，用户无法「看懂差别」。

`injectEveryNRounds` 在非 D 档 `disabled` 并给出说明；`preserveCodeTerms` 用 `role="switch"` + `aria-checked`；`extraRules` / `overrideHead` 用本地草稿 + 「保存 / 放弃更改」，`overrideHead` 收在 `<details>` 里；每个字段带「恢复默认」（`form.unset`）。

### 4.5 快速语言切换

`<button aria-haspopup="menu" aria-expanded>` + 自绘 SVG 图标：`wide` 时图标 + 语言自称 + `▾`，rail 时只有图标（`aria-label` 仍完整）。点击展开下拉菜单（不循环切换），菜单在组件树内 `position: absolute`（**不 portal 到 body、不用 `fixed`**：侧栏折叠用 `transform`，会改变 `fixed` 的包含块）。

键盘：Enter / Space 打开，Escape 关闭并回焦，↑↓ 在触发按钮上直接打开并选中相邻项，菜单内 ↑↓ 循环移动焦点。`pointerdown` 与 `keydown` 监听在 `useEffect` 内注册、清理函数内移除；菜单项焦点用 `ref` 数组管理，不用 `querySelector`。

**菜单第一项是「自动」（0.2.0 新增）**，后面才是五个预设。自动态下按钮标签读作「自动，简体中文」（`quick.menu.autoShort`），菜单标题行读作「当前自动解析为 简体中文」（`quick.menu.autoHint`）；手动态仍是「当前：X」。菜单项总数 6，`role="menuitemradio"` 与键盘导航逻辑不变（`itemRefs` 数组做焦点管理，不用 `querySelector`）。

### 6.3.1 镜像段回归防护（`scripts/verify-mirror.mjs`，清单 M14）

`client.js` 里那段「语言模式常量与解析规则」是 `lib/language.js` 的**手抄副本**——Client 是独立 bundle，`window.__ModuleLoader__.load` 的 factory 只能 `require('react')`，不能相对 import 包内其他文件。抄两份就必须有判据守住一致性。

**为什么此前是零覆盖（评审报告 8.5 节的 G1）：**

- `scripts/verify-language.mjs` 只 import `../lib/language.js`，**从不读 `client.js`**；它的【镜像 O1】【镜像 O3】两条断言虽然名字带「镜像」，测的却是 Host 侧自己；

**现在由 `scripts/verify-mirror.mjs` 兜住**（清单 M14 调用它）：

1. 从 `client.js` 抽出镜像段 —— 起点 `const BCP47 =`，终点 `/** 语言标签 → 显示名`。起点必须是 `BCP47`：从 `const MODE_AUTO =` 起抽会漏掉正则，`normalizeLocaleId` 一调用就 `ReferenceError: BCP47 is not defined`。任一标记找不到都**明确报错并 exit 1**，绝不静默通过。

4. 不一致时打印「函数名 + 入参 + host 输出 + client 输出」（最多前 10 条）并 exit 1；全一致时打印用例数并 exit 0。

### 6.3.2 顺带修掉的一处两侧不等价（`defaultLanguage` 兜底形态）

写 `verify-mirror.mjs` 时，`DEFAULTS` 维度加入假值立刻撞出真实分叉：

| | `defaultLanguage` 的兜底写法 | 对 `undefined` | 对 `''` | 对 `null` |
| --- | --- | --- | --- | --- |
| Host（`lib/language.js:103/130/147`） | 默认参数 `defaultLanguage = 'zh-CN'` | 兜底 | **原样** | **原样** |
| Client（改前） | `(input && input.defaultLanguage) \|\| DEFAULT_LANGUAGE` | 兜底 | 兜底 | 兜底 |

实测分叉：传 `defaultLanguage: ''` 时 Host 判 `manual`、Client 判 `auto`；传 `null` 时 Host 判 `manual`、Client 判 `auto`。

**修法不是 `??`。** `??` 只对 `null` / `undefined` 兜底，对 `''` 原样 —— 它修好了 `''`，但 `null` 仍会兜底成 `'zh-CN'`，与 Host 的默认参数语义（只认 `undefined`）依旧不等价。实测对照：

```
"zh-CN"    host=auto    ??=auto      ===undefined=auto
"en"       host=manual  ??=manual    ===undefined=manual
"ja"       host=manual  ??=manual    ===undefined=manual
""         host=manual  ??=manual    ===undefined=manual
null       host=manual  ??=auto  ←   ===undefined=manual   ← 只有这个与 Host 一致
undefined  host=auto    ??=auto      ===undefined=auto
```

所以 Client 侧新增 `pickDefaultLanguage(input)`，**精确模拟默认参数**：

```js
function pickDefaultLanguage(input) {
  const given = input ? input.defaultLanguage : undefined;
  return given === undefined ? DEFAULT_LANGUAGE : given;
}
```

三处（`effectiveMode` / `resolveTargetLanguage` / `resolveSource`）统一改调它。改完 `defaultLanguage` 这一维才真正等价，`DEFAULTS` 才敢放 `['zh-CN', 'en', 'ja', '', null, undefined]`。

> 附注：`defaultLanguage` 传 `''` / `null` 时 Host 会返回非 BCP-47 值（函数签名声明的是 `string`，这是 Host 侧的宽松边界）。两侧行为**一致地不可依赖**，矩阵纳入假值是为了证明「对假值的反应也一致」，不是鼓励这样调用。

**更强的自证法（README 两版的「验证」章节用的就是这套，已亲手跑通）**：不看界面表现，直接看模型收到了什么。DSH 把每次请求的 system prompt 记成 `system/message` 事件，落在 `~/.dsh/sessions/<转义工作目录>/<session id>/session.v4.jsonl.zstd`。

```bash
latest=$(ls -t "$HOME"/.dsh/sessions/*/*/session.v4.jsonl.zstd | head -1)
zstd -dc "$latest" > /tmp/dsh-session.jsonl   # macOS 无 zstd 先 brew install zstd
node -e '
const fs = require("node:fs");
const lines = fs.readFileSync("/tmp/dsh-session.jsonl", "utf8").split("\n").filter(Boolean);
const sys = lines.map((l) => JSON.parse(l)).filter((o) => o.type === "system/message");
const marks = ["【语言锁定 · 最高优先级】", "【语言锁定 · 中段重申】", "【语言锁定 · 收尾复述】"];
console.log("system 节点数:", sys.length);
sys.forEach((o, i) => {
  const text = o.data.message.content.map((p) => p.text || "").join("");
  const hit = marks.filter((m) => text.includes(m)).length;
  console.log(`#${i} turn=${o.data.turn} step=${o.data.step} 长度=${text.length} 三段命中=${hit}/3`);
});
'
```

判读：C / D 档应为 `三段命中=3/3`；切到 B 档后新节点应为 `2/3`，且长度比上一个节点**恰好短 118 字符**（mid 段长度）；停用插件后为 `0/3`。

`system/message` 的 `data` 结构为 `{turn, step, message: {role:'system', content:[{type:'text', text}]}}`。同目录下 `request/header` 事件体量最大（实测 122083 字符，含全部 tools 定义），不要拿它当 system prompt 读。

补充：D 档的日志证据是 `user/message` 事件里 `data.message.source.kind === "language-guard"`（`form: "notice"`、`summary: "语言自检"`）；若走 `agent.inject()` 路径则证据是 `agent/inbox/spliced`，本插件默认不用它。

## 7. 已知限制

与 `README.md` / `README.zh.md` 的「已知限制」一节保持一致（README 面向用户，本节面向维护者，条目一一对应）：

- 提醒消息会作为一条会话记录出现，可在日志中看到（决策已接受，面板说明里对用户写明）；
- **界面上的观感是折叠一行「上下文注入 · language-guard · 语言自检」**：`dsh-client-ui-chat` 把 `source.kind` 原样当注入标签渲染（`contextProducer()` 的 default 分支返回 `{role:"inject", label: kind}`），所以英文标识符 `language-guard` 无法隐藏，官方 `agent-instructions`、`skill-invocation` 同样如此。要本地化必须为上下文节点写自定义 `conversation.chat.node` 渲染器，首版不做；
- Client 半拿不到轮次计数，因此不展示「当前第几轮会注入」；
- 自定义语言只能在设置页文本框输入，快速切换菜单只列 5 个预设；
- **约束模板本身是写死的简体中文**，只替换 `⟨LANG⟩` / `⟨CODE⟩`，因此 `targetLanguage: "en"` 时注入文本是「中文框架 + English」混排。模型可正常处理，但行文未本地化，模板本地化留待后续版本；
- **绝对锁定，不给单轮开口子**（0.3.2 起明确）：用户当轮说「这次用英文回答」也不切换语言。语义是「设定一次、全程有效」；要换语言改设置或用 `/language`；
- **周期档不唤醒空闲会话**：`agent/pre-step` 只在轮次运行中触发，不发消息就没有提醒；
- **`mid` 位置可能被未来插件挤压**：若有插件在 order `5000`–`9000` 之间插段，「工具说明之后」的语义会被稀释；届时把 `mid` 提到 `8900`（仍在 `9000` 之前），再无效则回退 B 档；
- **切档会改变 system prompt**，DSH 因此追加一个新的 system 节点（in-history 替换），是一次性 token 开销，属预期行为；
- 与 `dsh-context` 等第三方插件可能撞 order（`-2000` / `11200`），但不撞 name，共存稳定，代价是重复烧 token；面板与两个 locale 已常驻提示用户清空对方配置（D13），但插件**无法**自动检测对方是否安装（不做跨插件探测）。
- **无法自动区分简体与繁体。** DSH 内置界面语言只有 `zh` 与 `en`（`dsh-client-locale/lib/index.js:11` `LOCALE_IDS = ["zh","en"]`），`zh` 不区分简繁；而 Host 侧拿不到系统语言。因此界面语言为「中文」时，自动模式一律解析为 `zh-CN`。需要繁体输出的用户请把语言模式切到「手动」并选 `zh-TW`。实现侧对应 `lib/language.js` 的 `mapPreference` 只做 `primary === 'zh'` 判断，不做 `zh-Hant` 推断；
- **不自动跟随操作系统语言。** 插件读取的是你在 DSH 设置里选择的界面语言，不是操作系统语言。DSH 的 Host 进程以 `ELECTRON_RUN_AS_NODE=1` 运行，拿不到 Electron 的 `getLocale()`；Node 的 `Intl` 在该进程里恒为 `en-US`，用它会把中文用户误判成英文，所以我们选择不用它。**任何文档不得声称插件会识别系统语言**（`docs/验收清单.md` M 组与 README 两版均按此措辞）。
