本文件记录**已落盘代码的每个文件职责、关键实现决策与验证方式**。设计依据以三份决策文档为唯一真源：

- `docs/decisions/01-mechanism.md` —— 三档机制、四段约束文案、配置 schema
- `docs/decisions/02-panel.md` —— 设置面板与快速语言切换交互

实现若与上述文档冲突，以文档为准并修实现；文档自身笔误见第 8 节。

---

## 1. 用途

`dsh-language-guard` 是一个 DSH 插件（Host + Client 双半身），做一件事：**让 agent 在整段会话里用指定语言思考和回答**，默认简体中文。

它通过三条常驻 system prompt section（首、中、尾）施加约束，用 `agent/pre-step` 在 D 档周期性追加自检提醒，并在设置页与侧栏提供配置入口。

不做什么：

- 不改写模型的流式推理增量（不伪造「思考过程」）；
- 不监听系统提示词装配事件去增删宿主文本（只用 `ctx.systemPrompt.section()` 声明自己的段落）；
- 不 append 新 type 的会话事件；
- 不依赖任何第三方运行时包（`dependencies` 为空）。

## 3. Host 半实现要点

### 3.1 三个常驻 section

| name | order | B 档 | C 档（默认） | D 档 |
| --- | --- | --- | --- | --- |
| `language-guard:head` | `-2000` | 有文本 | 有文本 | 有文本 |
| `language-guard:mid` | `5100` | 返回 `""`（被过滤，不留空行） | 有文本 | 有文本 |
| `language-guard:tail` | `11200` | 有文本 | 有文本 | 有文本 |

- order 一律写**数字字面量**：`ctx.systemPrompt.section()` 对非有限数字直接抛 `TypeError`；`mid` 用 `5100` 而不是 `5000`，因为 `tools:sdk` 恰好是 `5000`，同序时 `language-guard:mid` 会按 name 的 code-unit 字典序排到工具说明之前，失去「工具说明之后重申」的作用。
- 三个 section **一次性注册、永不 dispose**：切档只切 `text()` 返回值，避免同名重复注册抛 `prompt section "…" is already registered`。
- 全部 `interpolate: false`：用户 `extraRules` 里若含 `{{`，插值会抛错并让整份 system prompt 装配失败。
- 三个 section 都不带 `complete: true`（>1 个会抛 `multiple complete prompt sections are active`）。
- 文本在一次会话内稳定：`text()` 只读配置与内存覆盖，不读轮次、时间、随机数，避免 in-history 替换与 KV cache 失效。

### 3.2 配置读取

`schema` 的字段是 schemastery 的 **ref**，不是普通值。`readField()` 统一处理：

```js
const ref = config?.[field];
if (ref !== undefined && ref !== null && typeof ref.get === 'function') return ref.get();
return ref;
```

所有取值都是**函数式**（`strength()`、`language()` …），在 `text()` 与 `pre-step` 里现取，不缓存到闭包外——配置改动后无需重启、无需重新 apply，下一步装配即生效。

非法值不抛错：`normalizeStrength` / `normalizeInterval` 回退到默认值并通过 `warnOnce()` 各告警一次（避免每步刷屏）。

### 3.3 D 档周期提醒（`lib/cycle.js`）

监听注册在**插件根 ctx**（`ctx.on('agent/pre-step', …)`），payload 自带 `agent`，因此不需要 `agent/created` + per-agent disposer，也不维护计数器（轮次来自 payload 的 `turn`）。

门禁顺序（任一不满足即原样返回）：

1. `const decision = await next()`，`decision.kind === 'reject'` → 返回原 decision；
2. 档位不是 `D` → 返回；
3. `step !== 1` → 返回（只在每轮第一步动手，否则轮次永远不结束）；
4. `decision.messages.length === 0` → 返回（否则会凭空造出一轮）；
5. `turn % N !== 0` → 返回；
6. 已有 `source.kind === 'language-guard'` 的消息 → 返回（幂等，防重复插入）；
7. 子代理跳过：`Math.max(agent.session.header.delegationDepth ?? 0, agent.options.subagentDepth ?? 0) !== 0` → 返回。

插入位置：`const lastClaimed = decision.messages.findLastIndex(m => messages.includes(m))`，然后 `decision.messages.toSpliced(lastClaimed + 1, 0, reminder)`——即插在「本轮真实用户输入之后、runtime context 之前」。

返回 `{ ...decision, messages: entered }`，**必须 spread**：`decision` 上还有 `startsRequestSeries` 等字段，只返回 `{kind, messages}` 会丢。

提醒消息用 `createUserMessage({ content: [{ type: 'text', text }], source: { kind: 'language-guard', form: 'notice', summary: '语言自检' } })` 构造，`source.kind` 绝不能是 `user` 或 `runtime-context`（派生历史据此区分插件注入与真实输入）。

### 3.4 `/language` 命令（`lib/commands.js`）

`ctx.inject(['commands'], child => child.effect(() => child.commands.register({...})))` 懒注册：缺 `commands` 服务的 headless 部署不该让插件永久 pending，否则 section 永远不会注册。

- `/language` → 报告当前语言与配置值；
- `/language ja` → 内存覆盖（不写配置），立即生效；
- `/language reset`（或 `default`）→ 清除覆盖，回到配置值；
- 非法 BCP-47 → 返回 `{kind: 'error'}`，与 `Config.targetLanguage` 用同一正则。

### 3.5 设置表单

`ctx.inject(['settings'], child => child.effect(() => child.settings.configure({ auto: false }, ctx.fiber)))`。

`auto: false` 表示「不要在设置页自动生成页面」，只提供 volatile 配置表单；表单 UI 由 Client 半自己渲染（DSH 不存在 schema→控件的自动渲染器）。

### 3.6 Config schema

```js
export const Config = z.object({
  targetLanguage:      z.string().default('zh-CN').pattern(BCP47).volatile(),
  strength:            z.union([z.const('B'), z.const('C'), z.const('D')]).default('C').volatile(),
  injectEveryNRounds:  z.number().min(3).max(50).step(1).default(8).volatile(),
  preserveCodeTerms:   z.boolean().default(true).volatile(),
  extraRules:          z.string().default('').volatile(),
  overrideHead:        z.string().default('').volatile(),
});
```

- 用 `@deepseek-ai/schemastery`，**不是** zod：设置页 `volatileForm` 只认 schemastery 的 `meta.volatile`。
- `.volatile()` 必须加在**每个字段**上，不能加在根对象（会报 `volatile fields require a fixed object path without an enclosing volatile field`）。
- `schemastery` 是 peer（optional），不进 `dependencies`。

## 4. Client 半实现要点（`client.js`）

### 4.1 装载与注册

```js
window.__ModuleLoader__.load({
  id: 'dsh-language-guard',           // 必须严格等于包名
  factory(require) { /* … */ return { inject: ['slots', 'locale', 'configForms'], apply }; },
});
```

factory 内无副作用（不写 DOM、不注册全局监听、不 `setInterval`）；只 `require('react')`，不 require 任何 `@deepseek-ai/dsh-client-ui-*` 包。

### 4.2 两个 slot

| slot | 定义 | 用途 |
| --- | --- | --- |
| `plugins.bundle.config` | `key: 'dsh-language-guard'`（bundle 包名）、`locale: 'languageGuard'` | 插件详情页里的配置卡片，处理 `view === 'summary'` 与 `'page'` 两种视图 |
| `sidebar.footer.action` | `id: 'language-guard'`、`order: 100`、`locale: 'languageGuard'` | 侧栏底部的快速语言切换 |

两个 slot 都包在 `ctx.effect(() => ctx.configForms.whileServed(['dsh-language-guard'], () => ctx.slots.inject(…)))` 里：插件未启用时表单服务不可用，此时不应注册 UI。

### 4.3 配置读写

`const form = ctx.configForms.get('dsh-language-guard')`；`inject()` 返回 `{ form, hooks: { guardForm: form }, onSet, onUnset }`。

组件侧优先用 renderer 由 `hooks` 生成的 `useGuardForm(identity)`，拿不到时用 `form` prop 自建 `subscribe`/`getSnapshot` 订阅；两条路径都无条件调用 hook，保证 hook 顺序稳定。写入一律走 `form.set(field, value)` / `form.unset(field)`，Client 半不直接读写 `ctx.config.*`。

### 4.4 三档控件

原生 radio group（`fieldset` + `legend` + 3 个同名 `input[type=radio]` + `aria-describedby`），三档说明并列可见，文案逐字取 `01-mechanism.md` 2.1；C 档带「推荐」徽标。不用 `select`：下拉一次只能看一档，用户无法「看懂差别」。

`injectEveryNRounds` 在非 D 档 `disabled` 并给出说明；`preserveCodeTerms` 用 `role="switch"` + `aria-checked`；`extraRules` / `overrideHead` 用本地草稿 + 「保存 / 放弃更改」，`overrideHead` 收在 `<details>` 里；每个字段带「恢复默认」（`form.unset`）。

### 4.5 快速语言切换

`<button aria-haspopup="menu" aria-expanded>` + 自绘 SVG 图标：`wide` 时图标 + 语言自称 + `▾`，rail 时只有图标（`aria-label` 仍完整）。点击展开下拉菜单（不循环切换），菜单在组件树内 `position: absolute`（**不 portal 到 body、不用 `fixed`**：侧栏折叠用 `transform`，会改变 `fixed` 的包含块）。

键盘：Enter / Space 打开，Escape 关闭并回焦，↑↓ 在触发按钮上直接打开并选中相邻项，菜单内 ↑↓ 循环移动焦点。`pointerdown` 与 `keydown` 监听在 `useEffect` 内注册、清理函数内移除；菜单项焦点用 `ref` 数组管理，不用 `querySelector`。

### 4.6 与 `dsh-context` 的共存提示（D13）

第三方插件 `dsh-context` 的 `promptPrefix` / `promptSuffix` 注册的 section order 与本插件**完全相同**（`-2000` / `11200`），功能上无害，但两边都在往 system prompt 里塞同位置文本，**重复消耗 token**。

首版选择「常驻提示」而不是「检测到才提示」（简单优先）：

- `client.js` 设置卡片底部一行 `t('notice.contextConflict')`，用 `--dsw-alias-label-tertiary` 着色 + `--dsw-alias-border-l1` 分隔线；
- `locale/zh.json` 与 `locale/en.json` 的 `meta.description` 各带一句（这两个文件按 `03-manifest.md` 5.1/5.2 只放 `meta.*`，因此不新增运行时键；运行时文案在 `client.js` 内联字典里）。

### 4.7 视觉与文案

- 只用 `--dsw-alias-*` 主题 token（焦点环用 `--dsw-focus-ring-color`，带 fallback），无字面颜色，无 `prefers-color-scheme` 分支，明暗完全交给宿主主题。
- 样式通过 React `<style>` 元素渲染，类名一律 `lg-` 前缀，不在模块体写 DOM。
- 可见文案全部走 `ctx.locale.register('languageGuard', { zh, en })` 的 44 个 key，zh / en key 集合完全一致（各 44 键，`node` 数键实测；早期本节写「43 个 key」是笔误）；不调用 `addLanguage`（语言清单由宿主维护）。

4. 长会话（≥8 轮）确认会话日志里出现「语言自检」记录（D 档）。

**更强的自证法（README 两版的「验证」章节用的就是这套，已亲手跑通）**：不看界面表现，直接看模型收到了什么。DSH 把每次请求的 system prompt 记成 `system/message` 事件，落在 `~/.dsh/sessions/<转义工作目录>/<session id>/session.v4.jsonl.zstd`。

```bash
latest=$(ls -t "$HOME"/.dsh/sessions/*/*/session.v4.jsonl.zstd | head -1)
zstd -dc "$latest" > /tmp/dsh-session.jsonl   # macOS 无 zstd 先 brew install zstd
node -e '
const fs = require("node:fs");
const lines = fs.readFileSync("/tmp/dsh-session.jsonl", "utf8").split("\n").filter(Boolean);
const sys = lines.map((l) => JSON.parse(l)).filter((o) => o.type === "system/message");
const marks = ["【语言锁定 · 最高优先级】", "【语言锁定 · 中段重申】", "【语言锁定 · 收尾复述】"];
console.log("system 节点数:", sys.length);
sys.forEach((o, i) => {
  const text = o.data.message.content.map((p) => p.text || "").join("");
  const hit = marks.filter((m) => text.includes(m)).length;
  console.log(`#${i} turn=${o.data.turn} step=${o.data.step} 长度=${text.length} 三段命中=${hit}/3`);
});
'
```

判读：C / D 档应为 `三段命中=3/3`；切到 B 档后新节点应为 `2/3`，且长度比上一个节点**恰好短 118 字符**（mid 段长度）；停用插件后为 `0/3`。

`system/message` 的 `data` 结构为 `{turn, step, message: {role:'system', content:[{type:'text', text}]}}`。同目录下 `request/header` 事件体量最大（实测 122083 字符，含全部 tools 定义），不要拿它当 system prompt 读。

## 7. 已知限制

与 `README.md` / `README.zh.md` 的「已知限制」一节保持一致（README 面向用户，本节面向维护者，条目一一对应）：

- 提醒消息会作为一条会话记录出现，可在日志中看到（决策已接受，面板说明里对用户写明）；
- **界面上的观感是折叠一行「上下文注入 · language-guard · 语言自检」**：`dsh-client-ui-chat` 把 `source.kind` 原样当注入标签渲染（`contextProducer()` 的 default 分支返回 `{role:"inject", label: kind}`），所以英文标识符 `language-guard` 无法隐藏，官方 `agent-instructions`、`skill-invocation` 同样如此。要本地化必须为上下文节点写自定义 `conversation.chat.node` 渲染器，首版不做；
- Client 半拿不到轮次计数，因此不展示「当前第几轮会注入」；
- 自定义语言只能在设置页文本框输入，快速切换菜单只列 5 个预设；
- **约束模板本身是写死的简体中文**，只替换 `⟨LANG⟩` / `⟨CODE⟩`，因此 `targetLanguage: "en"` 时注入文本是「中文框架 + English」混排。模型可正常处理，但行文未本地化，模板本地化留待后续版本；
- **不硬顶用户的显式指令**：system 层声明默认语言，但用户明确要求「这次用英文回答」时模型应照办；
- **周期档不唤醒空闲会话**：`agent/pre-step` 只在轮次运行中触发，不发消息就没有提醒；
- **`mid` 位置可能被未来插件挤压**：若有插件在 order `5000`–`9000` 之间插段，「工具说明之后」的语义会被稀释；届时把 `mid` 提到 `8900`（仍在 `9000` 之前），再无效则回退 B 档；
- **切档会改变 system prompt**，DSH 因此追加一个新的 system 节点（in-history 替换），是一次性 token 开销，属预期行为；
- 与 `dsh-context` 等第三方插件可能撞 order（`-2000` / `11200`），但不撞 name，共存稳定，代价是重复烧 token；面板与两个 locale 已常驻提示用户清空对方配置（D13），但插件**无法**自动检测对方是否安装（不做跨插件探测）。
