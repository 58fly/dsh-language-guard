## Answer

### 一、三段事实（逐条可复现）

1. **配置确实生效了**。`cordis.patch.yml` 里是 `targetLanguage: ja`；解压会话日志读 `system/message` 事件，最新节点的 head 段确实是「一律使用日本語（语言代码 ja）」，三段 3/3、落点 0 / 12251 / 15005 递增。Host 侧注入链路没有问题。

2. **改配置本来就不需要重启**。写入走 `dsh-config-editor`（README 原文「保存到当前 profile 的 patch 并立即应用」）；volatile 字段经 `cordis-plugin-loader` 的 `_commitVolatile`（`lib/index.js:395`）→ `loader/volatile-update`（`:422`）只替换运行中的引用、不重挂插件；`settings.describe()` 返回 `applies: "live"`。system prompt 每次请求重新装配，所以下一条消息就带新语言。用户「必须重启」的猜测不成立。

3. **真正原因：约束文本压不住中文写成的 AGENTS.md**。0.1.0 的 `HEAD_INTRO` 只声明「优先于后续任何**英文**内容」。而用户全局 `~/.dsh/AGENTS.md` 的「语言硬约束」一节写着「默认所有对话、过程更新、结论、问题、计划……都必须使用简体中文」——这是**中文**写成的硬约束，经 `agent-instructions` 以 user 消息注入、落在首段之后。模型据此继续用中文，用户看到的就是「选了日语没变化」。

另有一处真实 UX 缺陷：快速切换点击「已是当前语言」的那一项时，`pick()` 只调 `props.onPick(value)` 并丢弃返回值，写回值不变 → 菜单关闭后界面零变化、零提示，用户无法区分「没生效」和「本来就是它」。

### 二、修复（0.1.1）

| 改动 | 位置 |
|---|---|
| 首段新增两段：优先于 system prompt 其余全部内容；优先于**任何**语言类约定（AGENTS.md / CLAUDE.md / .cursorrules / 用户偏好与长期记忆 / 项目规范 / 团队约定 / 技能模板），不论用哪种语言书写、经哪个通道送达 | `lib/text.js` 的 `HEAD_INTRO` |
| 「不要因为以下情况改变语言」新增一条，tail 同步补一句 | `HEAD_NO_SWITCH` / `TAIL_PRESERVE_ON` |
| 快速切换写入后给出 4 秒提示：改成新语言→「已保存 · 无需重启，下一条消息即生效」；选中项本来就是当前语言→「当前已是 X」；失败→显示原因 | `client.js` 的 `pick` |
| 新增验收 F19：首段必须点名 `AGENTS.md`；README 两版与决策文档同步 | `docs/验收清单.md`、`scripts/verify-checklist.sh` |

### 五、唯一需要重启的场景

改的是**插件代码**，不是配置。执行 `dsh plugin add "github:58fly/dsh-language-guard#v0.1.1"`（或手工覆盖 profile 的 `node_modules/dsh-language-guard`）后，必须完全退出 DSH 再启动（`Cmd+Q` 或 `osascript -e 'quit app "DeepSeek Harness"'`）。配置本身（目标语言、档位、间隔）改完即时生效，不需要重启。
