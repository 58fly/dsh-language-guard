# 缺陷：发布说明第十一节 0.1.1 的 pack 尺寸被 0.1.2 覆盖（评审 O2，0.2.0 已修）

## Question

有两种修法：

先查清 41221 到底是什么。

## Answer

### 一、结论：选 B。O2 的现象成立，但结论不成立

41221 是 **0.1.1 的真实尺寸**，不是凭空数字。硬证据：

```
git archive v0.1.1 | tar -x -C /tmp/v011
cd /tmp/v011 && npm pack --dry-run --json
→ entryCount 14  size 41226  unpackedSize 124059
（同法 v0.1.2 → 41246 / 124132）
```

`unpackedSize` 与 tag v0.1.1 时文档记录**精确相等**（124059），`size` 差 5 B 属 gzip / npm 版本抖动。tag v0.1.1 上 `docs/发布说明.md:15`、`:103`、`:375` 与 `docs/实现说明.md:230` 全部写 `41221 / 124059`。

captain 独立复现了这一步（`git archive v0.1.1 | tar -x -C /tmp/v011chk` 后跑 `npm pack --dry-run --json`），得 `entryCount 14 size 41226 unpackedSize 124059`，与上述一致。

所以真正的缺陷是：**发布说明第十一节（0.1.1 变更）的「0.1.1」列，在 0.1.2 发布时被 0.1.2 的值覆盖了**（41240/124132）。41221 不是「无出处」，是被抹掉了。修法不是删举例，而是把被覆盖的记录补回来——这就是 B。

### 六、教训

「文档里查不到出处」有两种可能：**数字是错的**，或者**记录被覆盖了**。本次是后者。查证方式不是读文档互相印证（文档本身就是被怀疑对象），而是**回到被记录的那个历史时点重新实测**——`git archive <tag>` + 重跑 `npm pack`。
